# План публичной платформы «Муравьиная революция»

## Задача

Сайт для всех желающих: пользователь открывает библиотеку без регистрации; любой ведущий сможет создать собственную комнату, пригласить игроков, назначать отряды и проводить бой. ГМ обладает специальными правами **только в своей комнате**, а не во всей платформе.

## Стадия 0.1 — готовый визуальный прототип

- Общая навигация, страницы, палитра, адаптация.
- Каталог семи специализаций, поиск и фильтры.
- Встраивание утверждённых автономных листов без вмешательства в их игровые алгоритмы.
- Правила из единого утверждённого текста.
- Демонстрация будущей комнаты и панели ГМа.

Не реализованы: учётные записи, настоящие комнаты, совместный бой, бестиарий, права доступа.

## После утверждения интерфейса — основные этапы

### Этап 0.2. Общий игровой движок

Отделить описание специализаций от отображения: конфигурация (`squadTemplates`) задаёт состав, здоровье, защиту, ходы и действия. Игровой движок проверяет атаки, лечение, эффекты и отдых. Лист — лишь интерфейс для команд игрока. Не переписывать игровую логику каждой специализации по отдельности.

Вынести единый набор компонентов: карточка характеристик, панель мастерства, шкала ОЗ, отрядные иконки/стопки, действия, резервы, фракционные метки, журнал статусов. Удобная основа — React + Vite.

### Этап 0.3. Контент

- Бестиарий: `creatures` (утверждённые существа), роли, фракции, характеристики, способности, изображения.
- Справочник: общие правила и особенности классов отдельно.
- Лор Холэна: отдельные записи, которые можно редактировать без изменения интерфейса.

### Этап 0.4. Онлайн-комнаты

- `profiles`: видимое имя и идентификатор пользователя.
- `rooms`: уникальный ID, создатель, режим видимости, приглашение и настройки.
- `memberships`: участник конкретной комнаты + роль **GM** или **PLAYER**. У пользователя могут быть разные роли в разных комнатах.
- `room_squads`: игровые отряды, состояние ОЗ, резерв, эффекты, владельцы, видимость для игроков.
- `turns`: инициатива, текущий ход, раунд.
- `actions/events`: журнал игровых операций для аудита и восстановления состояния.

Вариант серверной части: Supabase (Auth, Postgres, Realtime). Для небольших нагрузок возможен бесплатный тариф, но придётся проверять актуальные квоты, доступность из РФ и ограничения сна неактивных проектов.

**Безопасность:** членство и роль проверяет сервер/база; изменение чужого здоровья, скрытых противников, выдача роли ГМа и разрешение долгого отдыха не должны зависеть только от отключённых кнопок в браузере. Атака и лечение меняют данные атомарно и проходят проверку допустимого действия. Секретные данные ГМа не отправляются браузеру игрока.

### Этап 0.5. Проверка и публикация

Проверить несколько мобильных и настольных браузеров, слабую сеть, реконнекты, одновременные действия двух игроков, разделение чужих комнат, доступ из России без VPN. После проверки публиковать через статический хостинг (например GitHub Pages) и бесплатный управляемый бэкенд при соблюдении лимитов.

## Решения, ожидающие согласования

- Как пользователь входит в комнату: гостевое имя без регистрации или зарегистрированный аккаунт. Для публичного запуска безопаснее позволить гостям участвовать, а создателям комнат предложить аккаунт для восстановления контроля над комнатой.
- Какие параметры видит обычный игрок у обнаруженного врага.
- Как хранить и экспортировать историю боя.
- Как ГМ публикует/создаёт собственный бестиарий и дополнения.

Эти вопросы не мешают утвердить первый визуальный прототип.


## Публичные и мастерские сведения (v0.3)
Мастерская редакция содержит информацию не для игроков. На статическом сайте нельзя безопасно скрыть секреты простыми кнопками или JS-проверкой: если файл опубликован, он доступен любому. Мастерские материалы должны храниться отдельно на сервере с авторизацией ГМа или оставаться локальными.


## v0.4 — новые подсистемы
Книги игроков (документы поступят позднее) не смешиваются с правилами конкретных паков. Каталог предметов хранится в items-data.js. Мультифильтры реализованы общими функциями, с ИЛИ внутри группы и И между группами.
