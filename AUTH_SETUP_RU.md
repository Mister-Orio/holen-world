# Мир Холэна · Настройка авторизации v0.9

Проект Supabase: `holen-world` (Frankfurt, Free), проект `xxxsirbvyjfowyfocost`.

## Что уже сделано
- Авторизация по почте + паролю через Supabase Auth (никаких собственных хешей паролей или service_role ключей на сайте).
- Игровой ник при регистрации; `public.profiles` создаётся серверным триггером, уникальность без учёта регистра.
- Таблица `public.characters` с фильтрацией по паку (`journeys` или `insects`). Включены RLS-политики: доступ к персонажам только у владельца.
- Вход, выход, обновление токенов, сброс пароля и профильная коллекция (заготовки персонажей).
- Локальная демонстрация комнат v0.9. **Она пока не связана с Supabase.**

## Обязательные настройки перед публичной регистрацией

1. Откройте [Auth → URL Configuration](https://supabase.com/dashboard/project/xxxsirbvyjfowyfocost/auth/url-configuration).
   - `Site URL`: `https://mister-orio.github.io/holen-world/`
   - В `Redirect URLs` разрешите тот же адрес. Не используйте wildcard `*` для всего интернета.
   - Сохраните настройки.
2. Проверьте в [Auth → Providers](https://supabase.com/dashboard/project/xxxsirbvyjfowyfocost/auth/providers), что `Email` включён и `Confirm email` включён.
3. Настройте внешний SMTP-провайдер на странице [Auth → SMTP Settings](https://supabase.com/dashboard/project/xxxsirbvyjfowyfocost/auth/smtp). Бесплатная встроенная отправка Supabase **не подходит для регистрации произвольных пользователей**. Сам SMTP может иметь свои лимиты и может потребовать подтверждения домена.
4. Проверьте реальную регистрацию тестового аккаунта, письмо подтверждения, вход, выход, восстановление пароля, создание персонажа и вход на другом устройстве. Не выкладывайте реальные пароли, секреты SMTP, `service_role` или секретные токены в GitHub и чат.

## Про комнаты
Комнаты v0.9 по-прежнему используют `localStorage` одного браузера и намеренно помечены как прототип; включена перестроенная рубка ГМа, списки игроков, выбор специализаций и ручное управление здоровьем. **При создании онлайн-комнат потребуется серверная проверка ролей**, RLS, синхронизация состояния и защита от одновременных конфликтующих действий.

## Безопасность
В исходниках GitHub Pages находится исключительно публичный Supabase publishable key; он разрешён для браузеров. Безопасность определяется политиками RLS и контролем доступа на сервере. Никогда не добавляйте сюда secret/service_role ключ.

Это ранняя альфа; до публичного запуска необходимо проверить работу API и почты из России без VPN и правовые требования к хранению пользовательских данных.
