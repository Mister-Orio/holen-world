# Мир Холэна — схема онлайн-платформы (проект)

## Цель
Любой зарегистрированный пользователь сможет создать комнату для выбранного пака, пригласить игроков и управлять одной общей сессией с ПК или телефона. ГМ видит скрытых противников и может назначать права. Игроки видят только разрешённую информацию и меняют только свои отряды.

## Предлагаемая технологическая связка
- Интерфейс: оставляем прототип с HTML/CSS/JS, затем по мере роста переносим общие листы в компоненты (React + Vite опционально), не переписывая всё одномоментно.
- Размещение: GitHub Pages для открытого статического сайта или аналогичный бесплатный статический хостинг.
- Синхронизация: Supabase (Auth + Postgres + Realtime + Edge Functions/SQL RPC) при согласовании. Без подключённого проекта Supabase реальных комнат нет.
- Локальное сохранение: кэш состояния и режим только для чтения при потере связи; сервер считается источником истины.

## Сущности базы данных
1. profiles: user_id, nickname, avatar_url, updated_at.
2. packs: id, title, version, is_public.
3. rooms: id, invite_code_hash, title, pack_id, owner_id, status, created_at.
4. room_members: room_id, user_id, role (gm|player|spectator), joined_at, is_active.
5. characters: id, owner_id, name, pack_id, sheet_version, data JSON.
6. squads: id, room_id, player_id, unit_type_id, current_hp, alive_count, max_hp, reserves, combat_state JSON, version.
7. encounter_units: id, room_id, visibility, team, unit_type_id, combat_state JSON, version.
8. encounters: id, room_id, phase, round, turn_index, ordered_initiative JSON.
9. activity_log: id, room_id, actor_id, action, target_id, before JSON, after JSON, created_at.

## Критичные права
- ГМ комнаты назначается только через защищённую серверную операцию, не через клиентский переключатель.
- Игрок меняет только отряды, которые сервер считает принадлежащими ему.
- ГМ управляет врагами, видимостью, инициативой, резервами и подтверждением долгого отдыха.
- Величины урона, лечения и зарядов меняются серверной атомарной операцией. Клиент посылает команду, а не произвольное новое здоровье.
- Секретные записи и скрытые противники НЕ пересылаются в клиентские выборки игроков; RLS, отдельные публичные представления.
- Сервер хранит журнал действий для отмены ошибочного хода и разрешения споров.
- При потере соединения запрещаем конфликтующие записи, показываем «Нет связи».
- У всех паков собственные наборы правил, параметры, версии. Комнаты фиксируют версию пака на момент создания, миграции проводятся осознанно.

## Минимальный релиз онлайн-комнат
1. Регистрация (или вход по одноразовой ссылке), ник и профиль.
2. Создать комнату, выбрать пак, сгенерировать одноразовый/обновляемый код приглашения.
3. Вступить по коду, получить роль «игрок», назначить себе/получить от ГМа отряд.
4. Обновления ОЗ, статусов и зарядов в реальном времени между двумя браузерами.
5. Базовая панель ГМа: список игроков, открытые и скрытые враги, журнал событий.
6. Серверная операция лечения санитаром: проверка доступных зарядов, текущего состояния и права игрока; дальность подтверждается ГМом, пока нет встроенной карты.
7. Тесты нескольких одновременно подключённых пользователей и работы без VPN из России.

## Вне первого сетевого релиза
Карта с жетонами, видеосвязь, внутриигровой голос, платёжная система, универсальный редактор магических эффектов, marketplace и модераторские инструменты масштабного портала.

## Порядок работы
Этап 1: создать репозиторий, опубликовать СТАТИЧЕСКУЮ v0.6 и убедиться, что pdf и листы открываются.
Этап 2: выбрать облачный сервер данных, создать ключи и безопасные таблицы/RLS.
Этап 3: вход и профиль, комнаты и членство, сетевое состояние.
Этап 4: панель ГМа и игровые команды, тесты и постепенно публичный релиз.

## Важно про документы
«Великий пакт 1.7» — полная исходная редакция, предоставленная автором для общего доступа, включая материалы, ранее помеченные как мастерские. Если понадобится скрыть часть книги, потребуется отдельная публичная редакция до размещения сайта в открытом интернете.
