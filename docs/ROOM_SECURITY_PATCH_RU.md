# Проверка и применение подготовленного патча

Патч: `supabase/migrations/20261009144000_harden_room_health_and_client_grants.sql`.

Это инкрементальная миграция поверх восьми миграций действующего проекта до `20261009132252`. Исходных миграций в Git пока нет. **Не считать эту папку полной историей и не запускать db reset/db push в рабочем проекте вслепую.**

## Что меняется
1. Журнал для игрока при включённом hide_enemy_hp маскирует исторические и текущие сообщения изменения ОЗ ГМом. Форматы добавления существа и решения заявки сохраняются. При видимых ОЗ и для ГМа журнал остаётся полным.
2. Отдых отклоняет NULL/неизвестный вид и завершённую комнату. FOR UPDATE на rooms сериализует его с закрытием комнаты.
3. У anon/PUBLIC отзываются права на profiles/characters; у authenticated — TRUNCATE/REFERENCES/TRIGGER. Существующие authenticated SELECT профиля и CRUD персонажей сохраняются. Правило UPDATE профиля уже есть, но табличного UPDATE до патча нет; патч его не добавляет.
4. Существующие ограничения лечения, заряды, характеристики и роли не меняются.

## Порядок
- Восстановить исходную схему и функции на изолированной тестовой базе. Не использовать production для fixture-теста.
- Сверить текущие определения snapshot/rest и ACL с аудитом. При изменениях в live-схеме сначала пересмотреть патч.
- Применить миграцию в тестовой базе.
- Запустить `tests/sql/room_security_regression.sql` пользователем postgres с остановкой на первой ошибке. В той же сессии заранее установить `SET app.holen_allow_fixture_tests = 'yes';` исключительно на тестовой базе; без явного флага скрипт откажется работать. Скрипт создаёт вымышленные записи в транзакции и завершает её ROLLBACK; не отправляет письма.
- Проверить двумя отдельными браузерными аккаунтами: скрытые ОЗ, вход/выход, отдых, закрытие, чужие комнаты, прямые запросы к защищённым таблицам.
- Отдельно проверить двумя SQL-сеансами конкуренцию отдыха и закрытия: если закрытие зафиксировано первым, отдых отклоняется; если отдых захватил строку первым, он завершается до закрытия.
- После успешного теста и решения о релизе применить SQL через управляемую миграцию, сверить GRANT/RLS/Advisor, обновить handoff. Слияние PR само по себе SQL не применяет.

## Выполненная в аудите проверка
Read-only PostgreSQL SELECT проверил 24 сочетания форматов журналов и ролей: 0 расхождений у нового предиката. Старый предикат пропускает текущие сообщения урона и лечения. Это проверка выражения, а не выполнение изменённой функции.

**Не выполнено:** применение миграции, запуск интеграционного fixture-теста, проверка конкурентных сеансов и браузерный E2E. В этой сессии нет работающей локальной среды или тестовой копии базы.

## Ограничения
Маскировка старых событий зависит от формата текста. При изменении форматов нужно расширять тесты; устойчивое последующее решение — тип события и отдельное безопасное представление для игрока. По исторической схеме маскируются все сообщения ручного изменения ОЗ ГМом при hide, включая союзные отряды: достоверного target_unit_id у старых событий нет.

Миграция проверяет MD5 исходных определений snapshot/rest и останавливается при расхождении. Это защита от перезаписи более нового кода; повторное применение уже применённого патча также будет отклонено.
